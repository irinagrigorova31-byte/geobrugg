# Примеры триплет-выхода — два варианта и что из них стандарт

Два реальных варианта реверс-анализа одной страницы (ниша «сервис Mercedes», `sp-mb.ru`, рынок
**Яндекс/РФ**) — держим как **учебный пример**, не как шаблон под копирку. Ниша здесь русская;
Яндекс-специфика (дублирование в Microdata, FAQPage как коммерческий фактор) применима ТОЛЬКО на
РФ-рынке (см. «ПАРАМЕТРЫ ЭТОЙ НИШИ» в `CLAUDE.md`). **Технические и governance-правила ниже —
универсальны.**

## Файлы
- `variant-1-reverse-analysis.md` — реверс-анализ прозой: TL;DR, частотность X/6 по прочитанным
  конкурентам, пустоты рынка, проект структуры экранов, FAQ из PAA, этапность, честные Caveats.
- `variant-2-atomic-matrix.xlsx` — атомарная матрица: Субъект/Предикат/Объект, тип, «есть сейчас»,
  источник значения, куда внедрять, приоритет P0–P2; листы «Паспорт фактов», «Интенты и FAQ (SERP)»,
  «Конкуренты», «Внедрение».

## Что забираем из каждого (сильные стороны — в стандарт)
- **Из Варианта 1:** частотность **X/N по фактически прочитанным** конкурентам (N = число полностью
  прочитанных страниц; SERP-only домены учитываются отдельно, не в X/N); **пустоты рынка** (0/N —
  предикаты, которых нет ни у кого, а аудитории нужны — занимать первыми); **FAQ из PAA/«Похожих
  вопросов»**; **этапность** внедрения; **честные Caveats** (что не подтверждено).
- **Из Варианта 2:** **атомарные** триплеты (одна тройка = одна связь), **матрица**, приоритеты
  **P0–P3**, **измеримость** и явный статус «есть/нет сейчас».

Стандарт = **объединённый**: контент Варианта 1 в матрице Варианта 2, с колонками
`частотность X/N · тип · статус наличия (3 состояния) · блок · Schema.org (корректный) · куда
внедрять · приоритет P0–P3 · подтверждено клиентом · риск · источник URL · дата проверки`.
Формат матрицы и статусы — в `.claude/agents/triplet-collector.md` §7.

## Ошибки Варианта 2, ставшие постоянными правилами (учиться на них)
Разметочные промахи из этого разбора вынесены в **`docs/schema-org-cheatsheet.md`** как правила:
- `instrument` — только у `Action`, не у `Service` (оборудование/XENTRY — текстом);
- `sameAs` бренда (напр. Q36008) — только внутри под-сущности `brand`, не на организации;
- `warranty` — у `Offer` (`WarrantyPromise`), не у `Service`;
- **разметку нельзя ставить как KPI** (Яндекс не ранжирует по schema; Google FAQ-rich на коммерции
  почти не даёт; self-serving `AggregateRating` звёзд в органике не даёт) — «получить rich-сниппет»
  из целей убрать.

## Governance заявлений (постоянное правило)
Заявления, которые нельзя проверить по прочитанным страницам или `input/company.md` — оборудование,
«дешевле дилера», срок гарантии, % экономии, «ТО не у дилера сохраняет гарантию», спорное гео —
получают статус **«подтвердить у клиента до публикации»** (колонки «подтверждено клиентом» / «риск»
в матрице). Жизненный цикл: `to-check → confirmed → publish`. Правовые/гарантийные заявления до
подтверждения даём **условной формулировкой** (со ссылкой на норму, если она есть), а не как
безусловный факт. Проверяет gist-auditor (§ «Governance заявлений»); маркирует triplet-collector (§7).
