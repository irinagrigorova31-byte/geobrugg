## 2. Рабочий цикл (проверенный)

1. Пользователь даёт выгрузку топа (CSV/XLSX с колонками Группа / Фраза / Домен / URL).
2. Парсинг: связать фразы с группами, собрать топ-20 URL по каждой, **удалить дубли доменов**, посчитать частоту домена в группе.
3. Реверс: зайти на реальные страницы лидеров, извлечь триплеты из содержимого (НЕ из общего знания!).
4. Суммировать по группе с частотностью X/Y (у скольких доменов группы встречается триплет).
5. Пометить: ОБЯЗАТЕЛЬНЫЙ (≥70% доменов) / ОТСТРОЙКА (≤34%).
6. Оформить: Excel (столбец = группа) и/или MD-отчёт.
7. По запросу — тексты на основе триплетов соседним столбцом.
8. **GIST-аудит перед выдачей** (мастер-файл III-6): вердикты по блокам, тест заменимости, дифференциатор в первой трети, FAQ-фильтр. Для серийных страниц (услуга × кузов/гео/объект) — правило незаменимого узла (III-7): страница без уникальной фактуры не публикуется.
9. **Техчек на гомоглифы** (III-6а): смешанные алфавиты в одном слове + невидимые символы (NBSP, SHY, ZWSP). Особое внимание — артикулы, коды ошибок, КТРУ/ОКПД2, кузова/двигатели, NAP, поля JSON-LD. Ошибка невидима глазом и рвёт распознавание сущности.

**Ключевое правило:** если в файле есть URL — триплеты извлекаются реверсом реальных страниц, а не из общего знания. Это принципиально.

**Исключения:** маркетплейсы (Ozon, WB, Яндекс.Маркет и т.п.) из анализа исключать, если запросы информационные.

### GIST-система (метод, разобран 31.07.2026)
- Изучены: gist-content-logic-skill v1/v2, промпты GIST-1/2/3, gist-prompts-pack, gist-checklist, посты канала.
- **Фактчек:** статья GIST реальна (Fahrbach et al., Google Research, NeurIPS 2025, arXiv:2405.18754), но это алгоритм отбора *обучающих данных* (сэмплирование ImageNet), не ранжирования; «потолок 56%» = порог NP-трудности аппроксимации задачи MDMS (0,5584); «Google внедрил GIST в поиск / массовые выпадения» — неподтверждённая спекуляция. Механика «полезность × разнообразие» реальна (MMR 1998, диверсификация, RAG-отбор).
- **Вердикт:** tripl полнее (5 слоёв + сущности + разметка + внешний слой + Яндекс); GIST — редакторская надстройка над одним слоем. Взято 4 элемента → мастер-файл v2: слой I-2а, QC-аудит III-6 (рубрика блоков, тест заменимости, первая треть), правило незаменимого узла III-7 (анти-каннибализация матриц), FAQ-фильтр + предикаты «точки отказа».
- **Не взято:** нарратив 56% в клиентские документы, ограничение топ-3 вместо топ-20, резка обязательного ядра на коммерции Яндекса.
- GIST-файлы хранить отдельно как референс; в knowledge проекта не класть (дублируют интегрированное в v2).

## 4. Теоретические блоки (в отчётах чата, не в файлах)

- **Перелинковка + внешнее усиление сущностей:** pillar-cluster, silo, глоссарий как слой сущностей; инфо→коммерция 2–4 контекстные ссылки; анкор = каноническое имя сущности; сквозной `Organization/@id`; `about`/`mainEntity`/`isPartOf`; sameAs только на внешние.
- **Иерархия внешних подтверждений:** Wikidata → Яндекс.Бизнес/Карты/2ГИС/реестры → каталоги/отзовики → PR (VC, Habr, РБК) → Википедия.
- **Анкор-лист:** брендовые + безанкорные 60%+, коммерческие минимально (Минусинск).
- **Соцсигналы:** НЕ прямой фактор (Cutts 2014, Mueller 2015, Illyes 2016) — работают косвенно через брендовый спрос и sameAs.
- **Распознавание отсутствия knowledge panel:** инкогнито + брендовый запрос; отличать панель знаний от карточки Бизнеса; Google KG Search API + kgmid; принудительный вызов `?kgmid=`.

## 5. Технические заметки

- Инструмент глубокого исследования периодически отваливается («tool not found») — помогает повтор через 1–2 сообщения.
- JSON-LD конкурентов дословно обычно НЕ извлекается (script-теги срезаются) — выводы по видимым признакам + og-тегам; финальная проверка через валидатор Яндекс.Вебмастера и Google Rich Results Test.
- При ошибке чтения файла (`OSError: Input/output error`) — повторить из `/home/claude`.
- Кодировка CSV: `utf-8-sig`, разделитель `;`.
- **Гомоглифы:** правило «в одном слове один алфавит»; скрипт-чек в мастер-файле III-6а. Источники заражения — копипаст из Word/PDF/Figma/мессенджеров и русская раскладка при наборе латинских артикулов. Кириллические домены (IDN) — не гомоглиф-атака: punycode в href/JSON-LD, кириллица в видимом тексте.
