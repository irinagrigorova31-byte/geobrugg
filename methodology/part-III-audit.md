## 6. GIST-аудит готового текста (QC-слой, обязательный перед выдачей)

Выполняется **после** генерации текста по матрице триплетов (шаг 7 рабочего цикла) и **до**
передачи клиенту/публикации. Цель — не косметика, а отбор: убрать заменимое, поднять
незаменимое. Проверенный триплетный контент проходит аудит быстро; процедура ловит воду,
внутренние дубли и «ещё одну хорошую, но заменимую страницу».

**Процедура (по блокам H2/крупным секциям):**
1. Разбить страницу на блоки; у каждого блока должна быть одна ясная функция. Два блока с
   одной функцией → объединить, оставив сильный.
2. Оценить каждый блок по рубрике и вынести вердикт (без вердикта блок не остаётся):

| Измерение | Шкала |
|---|---|
| Полезность (помогает решить/выбрать/действовать) | высокая / средняя / низкая |
| Риск избыточности (повтор лидеров или соседнего блока) | низкий / средний / высокий / критический |
| Отличимость (есть ли здесь незаменимый узел) | высокая / средняя / низкая |
| Вердикт | оставить / сжать / переписать / объединить / поднять выше / удалить |

Решающие правила: обязательное ядро + высокая избыточность = **сжать, не раздувать**;
высокая отличимость + высокая полезность = **поднять выше**; низкая полезность + высокая
избыточность = **удалить**.

3. **Тест заменимости страницы:** можно ли заменить её лидером топа без заметной потери пользы?
   Можно ли заменить первые 3 блока типовым контентом конкурента? Если да → пересборка, а не правка.
4. **Тест первой трети:** главный дифференциатор (сильнейшая отстройка из матрицы) виден в
   первой трети страницы. Если спрятан ниже — поднять.
5. **FAQ-фильтр:** FAQ оставляется, только если каждый вопрос добавляет новый узел (ограничение,
   исключение, порог, точку отказа), а не пересказывает тело текста и не служит свалкой хвостов
   семантики. Вопросы-пересказы — удалить или слить в тело.
6. **Проверка «точек отказа»:** есть ли на странице хотя бы один блок «когда не сработает /
   кому не подходит / цена ошибки», если он релевантен теме. Нет → добавить из матрицы.
7. **Техническая гигиена текста (гомоглифы и невидимые символы).** Проверить обязательно —
   ошибка невидима глазом и обесценивает работу целиком. См. III-6а.
8. **Финальный вердикт** (один из): готово к публикации / готово после мелких правок / нужна
   итерация / слишком слабо. Не «готово» → назвать причину: заменимость / слабый дифференциатор /
   нет доказательств / шаблонная структура / вода / нет ключевых узлов / смешанные алфавиты.

**Границы применения:** на коммерческих посадочных Яндекса аудит НЕ трогает обязательное ядро
(прайс в HTML, гарантия, NAP, кузова/бренды, FAQPage-разметку под Яндекс) — см. оговорку I-2а.
Режется только дублирующий и водянистый слой поверх ядра.

## 6а. Гомоглифы и невидимые символы (обязательный техчек)

**Что это.** Гомоглифы — символы разных алфавитов с одинаковым начертанием, но разными кодами
Unicode: кириллическая «а» (U+0430) и латинская «a» (U+0061) визуально идентичны, для машины —
разные токены. Пересекающийся набор кириллица/латиница: **а с е о р х у А В Е К М Н О Р С Т Х**,
плюс греческие ο ν α ρ, математические alphanumeric symbols и полноширинные формы.

**Почему это ломает именно триплеты и GIST:**
- **Сущность не распознаётся.** Триплет — утверждение о сущности, сущность опознаётся по строке.
  «Mercedes» с кириллической «е» — не узел графа знаний, а неизвестный токен: связь не возникает,
  sameAs не срабатывает, `"name"` в JSON-LD проходит валидатор и не склеивается ни с чем.
- **Страница вылетает из отбора (слой I-2а).** Семантическая близость считается по эмбеддингам;
  текст с вкраплениями гомоглифов токенизируется рвано. Страница не «слишком похожа на лидера» —
  она нечитаема и не попадает в кластер кандидатов вообще.
- **Артикулы и коды перестают находиться.** `A0009890807`, `W212`, `OM651`, `ATF 236.14`, `КТРУ
  26.60.13.190` с одной подменённой буквой не находятся ни поиском по сайту, ни поисковиком.
  В нишах с номенклатурой (автосервис, медтехника, запчасти) это самая дорогая из ошибок.

**Откуда берутся (по убыванию частоты):**
1. Копипаст из Word, PDF, Figma, мессенджеров — вместе с неразрывными пробелами (U+00A0),
   мягкими переносами (U+00AD), zero-width space (U+200B), «умными» кавычками и длинными тире.
2. Русская раскладка при наборе латинских артикулов на автомате (А вместо A, С вместо C).
3. Намеренная подмена как старая техника обхода антиспам-фильтров и проверок уникальности —
   сегодня работает только против самого сайта.

**Правило проверки:** в одном слове не должно быть двух алфавитов.

```python
import re, unicodedata
def mixed_script(text):
    """Вернёт слова, где смешаны алфавиты (кириллица+латиница и т.п.)."""
    for word in re.findall(r'\w+', text):
        scripts = {unicodedata.name(c, '').split()[0] for c in word if c.isalpha()}
        if len(scripts) > 1:
            yield word, scripts

INVISIBLE = {'\u00a0': ' ', '\u00ad': '', '\u200b': '', '\u2060': '', '\ufeff': ''}
def clean_invisible(text):
    for k, v in INVISIBLE.items():
        text = text.replace(k, v)
    return text
```

**Что прогонять обязательно:** готовые тексты перед сдачей; прайсы и таблицы; все артикулы,
коды ошибок, коды КТРУ/ОКПД2, обозначения кузовов и двигателей; NAP-блок и футер; поля JSON-LD.

**Отдельно про домены.** Гомоглифы породили класс атак на IDN (`аpple.com` — здесь «а»
кириллическая **намеренно**, это живой пример: прогон чека выше найдёт это слово в самом
мастер-файле, и это ожидаемо — не «исправлять»);
браузеры показывают punycode при подозрительном смешении алфавитов. Полностью кириллический домен
(например `провайдеры.рус` → `xn--80adhes1agig4i.xn--p1acf`) — легитимный IDN, а не подделка:
punycode в href/JSON-LD и кириллица в видимом тексте — норма, см. правило в отраслевых кейсах.

## 7. Правило незаменимого узла (анти-каннибализация матричных страниц)

Применяется к любым сериям страниц из одного шаблона: «услуга × кузов/двигатель» (автосервис),
dom/street-страницы (провайдеры), «услуга × объект» (ДДД), «уровень × формат» (школа).

**Правило:** страница серии публикуется, только если несёт ≥1 незаменимый узел — фактуру,
специфичную именно для этой комбинации, которую нельзя перенести на соседнюю страницу серии
без потери смысла. Примеры узлов: дефект балансирного вала только у M272/M273 (TSB, серийные
номера); ATF 236.14/236.15 по дате выпуска только у 722.9; цепь ГРМ сзади только у OM651;
реальные провайдеры/технология GPON конкретного дома; СанПиН-требование конкретного типа объекта.

**Тест симметрии кластера:** если страницы серии можно поменять местами (или удалить половину)
без потери смысла — это не архитектура, а дублирующий массив = самосозданный конфликтный радиус
и дорвей-риск в Яндексе. Лечение: (а) добить незаменимые узлы из реверса/инвентаризации;
(б) развести страницы по интентам (выбор / сравнение / процедура / неисправность / ошибки),
а не по формулировкам ключа; (в) общую теорию вынести на одну опорную страницу (pillar),
на дочерних оставить только то, что меняется: цифры, ограничения, болячки, цены.

**Связь с методикой:** это усиление, а не замена анти-дорвейного правила (провайдеры, II-A) —
GIST-логика и дорвей-фильтр Яндекса наказывают одно и то же явление с двух сторон.

## Оговорки (общие)

- Разметка конкурентов в исследованиях — целевая модель по косвенным признакам (SPA/бот-защита),
  не копия кода. Проверять валидаторами перед копированием полей.
- Значения (цены, числа, номера) — заглушки, заменять реальными. Разметка = видимый текст слово в слово.
- Числа в нишах меняются (HSK, регуляторика, цены) — датировать факты, обновлять `dateModified`.
- Микроразметка — косвенный фактор (влияет через CTR/сниппеты/AI-ответы, не на позиции напрямую).
