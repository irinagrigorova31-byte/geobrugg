Выполни БЛОК 2 пайплайна tripl — проектирование ТЗ. Аргументы: $ARGUMENTS

Короткий блок — один агент и ворота. Оркеструешь сам, владелец ждёт результат.

# Предусловия
1. Прочитай CLAUDE.md.
2. Проверь, что БЛОК 1 отработал: существуют data/triplets.md (после merge),
   data/entities.md, data/domain-assets.md, .claude/skills/project-<slug>/SKILL.md.
   Чего-то нет → ОСТАНОВИСЬ, скажи, что сначала /tripl-collect.
3. Дополни review/run-log.md.

# ЭТАП 4 — tz-writer
Запусти tz-writer.
Вход: triplets.md (+ карта подтем), entities.md (карта URL — авторитетна),
domain-assets.md (незаменимые узлы), скилл ниши (YMYL, запрещённые формулировки),
part-II-otrasli.md.
Выход: data/tz/tz-NN.md на каждую страницу + data/external-tasks.md.

Проверь: файлы ТЗ созданы, в отчёте есть таблица «кластер → tz-NN».

# ВОРОТА-СТОП: блокеры
Из отчёта tz-writer собери блокеры — страницы без незаменимого узла (серийные)
и без YMYL-подписанта. Если блокеры есть:
- выпиши их списком в run-log и покажи владельцу;
- СПРОСИ: писать все страницы или только без блокеров?
- дождись ответа, дальше работай только по утверждённому списку.

После утверждения списка: если появился slug проекта и его ещё нет в шапке
copywriter.md — допиши туда поле skills: project-<slug> (рядом с humanizer).

# ВОРОТА БЛОКА 2 — покажи владельцу и остановись
Выведи для проверки:
- сколько ТЗ создано, по каким сущностям;
- таблица «кластер(ы) → tz-NN» — как разошлась нарезка;
- блокеры и решение по ним;
- пары кластеров со слиянием (пересечение ≥70% из этапа 1) — разведены ли;
- сколько задач ушло в external-tasks.md;
- чего не хватило в матрице (вопросы клиенту).
Владельцу проверить главное: структура НЕ копирует каркас топа, дифференциатор
заложен в первую треть, слияния разведены правильно.
Дальше НЕ иди. Следующий блок — /tripl-write.
