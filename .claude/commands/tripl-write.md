Выполни БЛОК 3 пайплайна tripl — производство текстов. Аргументы: $ARGUMENTS

Здесь два цикла и одна архитектурная петля. Оркеструешь сам, следи за лимитами
итераций строго.

# Предусловия
1. Прочитай CLAUDE.md.
2. Проверь: есть data/tz/ с файлами ТЗ. Нет → ОСТАНОВИСЬ, сначала /tripl-tz.
3. Возьми утверждённый на прошлом блоке список страниц (все или без блокеров).
4. Дополни review/run-log.md.

# Правила лимитов (соблюдать)
- copywriter — волнами по 5-6 экземпляров, не залпом (лимиты API).
- Переписывание после аудита — МАКС 3 круга.
- При 529/лимите у экземпляра — пауза 60 сек, удали недописанный drafts/page-NN.md,
  один перезапуск.

# ЭТАП 5 — copywriter (параллельно)
По экземпляру на каждое утверждённое ТЗ, волнами по 5-6, все Task одним сообщением
в волне. Каждому передай: путь к его ТЗ и путь к drafts/page-NN.md.
Внутри каждый сам: humanizer + сверка с ТЗ + гомоглиф-чек за собой.
Дождись волны, потом следующую.

# ЭТАП 6 — аудит и переписывание (цикл, макс 3)
6.1. Запусти gist-auditor параллельно на каждый текст. Каждому — путь к тексту.
     Выход: review/audit-NN.md.
6.2. Собери статусы из audit-NN.md:
     - «готово к публикации» → страница выходит из цикла;
     - «готово после мелких правок» / «нужна итерация» / «слишком слабо» →
       в список переписывания. «слишком слабо» отдельно пометь в run-log.
6.3. Для списка переписывания: параллельно copywriter ТОЛЬКО по этим страницам
     (каждому передай путь к его audit-NN.md), затем снова gist-auditor по ним же.
6.4. Повторяй 6.2-6.3, максимум 3 круга.
     СТОП-1: «слишком слабо» дважды подряд по одной странице → вынь её из цикла,
     покажи владельцу — проблема в ТЗ или данных, не в тексте.
     СТОП-2: после 3-го круга остались непринятые → ОСТАНОВИСЬ, покажи список
     со статусами.

# ЭТАП 7 — cluster-inspector
Запусти cluster-inspector. Выход: review/cluster-report.md.
Разбери вердикт:
- «архитектура состоятельна» → к воротам блока;
- «точечные дыры» → выполни рекомендации через указанных в отчёте агентов
  (обычно copywriter точечно), затем повторный cluster-inspector;
- «дублирующий массив» → ВОРОТА-СТОП: ОСТАНОВИСЬ, покажи отчёт владельцу.
  Возврат в архитектуру (entity-mapper / tz-writer) — решение владельца, не
  автоматика: он обесценивает часть готовых текстов. Сам не запускай возврат.

# ВОРОТА БЛОКА 3 — покажи владельцу и остановись
Выведи для проверки:
- сколько текстов написано, сколько прошли аудит с первого раза;
- сколько кругов переписывания понадобилось;
- страницы, вынутые из цикла (проблема в ТЗ/данных);
- вердикт cluster-inspector;
- заглушки [ТРЕБУЕТСЯ] по всем текстам — сведи в один список для клиента.
Владельцу прочитать тексты: проходят ли на вкус, не водянистые, дифференциатор
в начале. Слабые → переписать сейчас, до оформления (дешевле).
