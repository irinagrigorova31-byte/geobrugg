# external-PLATFORM — как подключить площадку

`external-PLATFORM` — **пустой шаблон** правил одной сторонней площадки для off-site-ветки
(GEO-размещения, чтобы бренд цитировался в AI-выдаче). Он не рабочий: его копируют под реальную
площадку и заполняют.

## Как склонировать под площадку

1. Скопируй папку `external-PLATFORM/` в `external-<platform>/`, где `<platform>` — slug реальной
   площадки латиницей: `external-reddit`, `external-tripadvisor`, `external-medium`, `external-quora`
   и т. п. Slug должен совпадать с тем, что указывают в плане размещений и в off-site-ТЗ.
2. В `SKILL.md` поставь `name: external-<platform>` и перепиши `description` под конкретную площадку.
3. **Заполни все разделы `SKILL.md` из инструкции владельца площадки** — её TOS, редполитики, гайда
   для авторов: Формат и длина; Лимиты TOS / самопиара; Политика бэклинка на свой сайт;
   Disclosure / авторство; Тон; Извлекаемость под AI-цитату. Ничего не выдумывать: нет правила —
   писать «нет данных».
4. Шаблон `external-PLATFORM/` не трогай — он остаётся заготовкой для следующих площадок.

## Разграничение: правила площадки против голоса бренда

- `external-<platform>` = **ПРАВИЛА ПЛОЩАДКИ** — подключаемый модуль, свой на каждую площадку
  (что можно постить, лимит самопиара, ссылки, disclosure, формат).
- `project-<slug>` = **АУДИТОРИЯ И ГОЛОС** — общий скилл ниши, один на проект, создаёт niche-expert
  (сегменты ЦА, словарь, запрещённые формулировки, тон бренда).

**external-copywriter грузит ОБА**: голос и словарь — из `project-<slug>`, правила площадки и
формат — из `external-<platform>`. Их же читают external-tz-writer (проектирует ТЗ под правила
площадки) и external-gist-auditor (проверяет соблюдение TOS/disclosure/бэклинка).
